# GPT 需求发现定时任务 SOP 草案（待用户审核，未启用）

版本 v0.1 / 2026-11-13。此文件是供未来 GPT 自动任务读取的执行规格，**并未创建任何定时任务**。

## 目标
发现适合单人低成本运营、英语 SEO 可获客的精品工具页、Micro SaaS、AI 图片/视频细分工具及 H5 游戏相关需求。优先开发验证时间在 7 天内、总计约 8–12 工时以内、可复用 Next.js/React/Tailwind/Cloudflare 或 Vercel 的机会。先需求验证，不直接开发。

## 启动前的强制阅读
1. 读取仓库 `https://github.com/owenlee669/reqs-geifei` 的 main 分支 `docs/methods.md` 和本文件的**最新版本**。
2. 阅读已有历史报告及候选库，做产品/关键词/痛点去重。没有历史数据时明确标记初次运行。
3. 文中原始分享是**方法**，不能当作当天新发现、也不能拿旧数据直接作为当前机会。
4. 若 GitHub 无法读取、某网站 403、无付费 API，记录不可用；改用公开可访问的合规数据，不准虚构查到的结果。

## 执行策略
- **P0 常规**：M01 新站榜单、M02 sitemap、M03 词根与 SERP、M04 商业验证、M05 差评/替代品、M06 社区求助。每轮最多聚焦两个发现渠道，优先深入核实，不为了数量扫全部网站。
- **P1 轮换**：M07 付费服务、M08 新模型/游戏、M09 GitHub Skills、M10 平台子域名、M11 自有站 GSC/GA4（需要有授权）。
- **P2 衍生**：M12 已验证需求细分化。
- 同一产品/痛点跨多个方法来源只算一个机会，保留方法 ID 列表。
- 不反复报告旧线索，除非新增独立证据、评分变化、趋势变化或状态升级。

## 每条候选必须经过的 8 步
1. **原始链接**：保存具体帖子/评论/产品功能页的直链、发布时间和查验日期。找不到具体直链则不能声称核实。
2. **用户动作**：用一句话表达「谁，在什么场景，需要完成什么操作，当前为何困难/贵/费时」。
3. **英文关键词**：从真实用户表述提炼 1–3 个英文 query；注明交易/工具使用/教程/替代/导航等搜索意图，默认研究英语市场，不机械直译中文。
4. **独立需求证据**：至少两条独立来源（非同作者转发/采录），记录支持的具体结论。
5. **商业化证据**：至少一条明确的付费替代、真实公开售价并有用户使用迹象、预算或购买/切换意愿、付费手工交付。不能把 Stripe 跳转/广告投放/榜单点赞当成交。
6. **SEO 实查**：按具体国家与日期检查 Google SERP 页面类型、意图、竞品及弱势站；有权威数据时记录 volume/KD/CPC/trend 与来源和时间，不可得就填 unknown，绝不估造。
7. **MVP**：写出一周 MVP 的具体输入/处理/输出、主要 API 依赖和成本、一个最小推广验证动作（例如落地页、试用、购买意向/早期付费）及风险。
8. **评分去重归档**：先算评分，再按证据门槛确定状态，记录去重键和复查日期。

## 状态与评分
- `Signal`：仅初步线索。
- `Keyword Candidate`：有明确英语搜索意图但还未完成验证。
- `Validated Opportunity`：必须有 ≥2 独立需求证据、≥1 商业化证据、SERP 和 MVP 可行性检查。
- `Watchlist`：等待第二证据/付费信息/趋势证实。
- `Rejected`：重复、超成本、搜索意图不匹配或法律版权风险过高。

| 维度 | 权重 | 判断 |
|---|---:|---|
| 真实痛点/独立来源 | 25 | 具体问题、复现与频率 |
| 商业化/付费证据 | 20 | 付费替代、预算、购买意愿 |
| SEO 获客机会 | 20 | 英文意图、SERP 缺口、竞争 |
| 7 天 MVP 可实现性 | 20 | 开发/接口/维护成本 |
| 持续性与差异化 | 15 | 是否非短期热点、可复购/重复使用 |

**≥75 分**仅为重点观察，不自动成为 Validated；60–74 分继续验证；<60 分观察或拒绝。付费线索缺失时不因总分高而升级。侵权、无法获得必要 API、不可承担的成本是单独的否决项。

## 输出格式（每条）

```markdown
### 候选名称 — 状态（Signal / Keyword Candidate / Validated Opportunity）
- 日期：首次发现 / 本次检查
- 方法：Mxx；去重键：规范化域名+搜索意图+用户问题
- 用户：谁 / 场景 / 高频操作与困境
- 用户动作：英文一句话
- 关键词：英文词1 / 词2 / 词3（各自意图）
- 证据1：原始直链 + 日期 + 简短原话或行为
- 证据2：独立原始直链 + 日期 + 简短原话或行为（没有则未验证）
- 付费信号：具体替代方案、定价或购买意愿 + 来源（没有则未验证）
- SERP：地区/日期、前列竞品、搜索结果类型、突破口
- 数据：volume、KD、CPC、trend及来源（无法查则 unknown）
- 评分：真实痛点x/25、商业化x/20、SEO x/20、MVP x/20、持续性x/15，合计x/100
- 7天 MVP：输入 → 处理 → 输出；试验方式；主要开发/运维成本
- 风险：版权/商标/API/数据访问/竞争
- 下一步：一个具体待验证动作
```

运行汇总：检查了哪些渠道、多少条原始信号、多少条去重、多少条升级、多少条淘汰、最多 3 个值得立即进一步验证的机会，以及访问失败/信息缺失。**无合格机会时如实写 0，不用拼凑日报。**

## 未来执行时建议的仓库存储
- `reports/YYYY-MM-DD.md`：逐日运行记录。
- `data/opportunities.jsonl`：长期候选池，包含 ID/first_seen/last_seen/status/evidence_url(s)/keywords/score。
- `data/checkpoints.json`：每个监测源的最近成功扫描时间、失败原因和增量标记。

写库前查旧文件与 SHA，避免覆盖其他任务，失败要报告。原始剪存目录始终只读，不改动。
